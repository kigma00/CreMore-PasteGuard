# CreMore PasteGuard

**한국어** | [English](README.en.md)

**지정한 Windows 앱이나 웹사이트에 텍스트를 붙여넣을 때, 등록한 정규식과 일치하는 문자열이 있으면 차단합니다. 클립보드 내용은 변경하지 않습니다.**

예를 들어 Slack에 토큰을 실수로 붙여넣지 않도록 설정할 수 있습니다. 토큰은 서비스의 인증이나 권한 확인에 사용하는 값입니다. 처음 사용할 때는 실제 비밀번호나 토큰 대신 아래 테스트 문자열로 동작을 확인하세요.

> Windows 앱에서는 `Ctrl+V` 또는 `Shift+Insert`로 붙여넣을 때 작동합니다. Windows 앱의 우클릭 메뉴를 통한 붙여넣기는 차단하지 않습니다.

## 실행 준비

Windows 10 또는 11과 .NET Framework 4.8이 필요합니다. 별도 서버나 서비스 계정은 필요하지 않습니다.

### 실행용 ZIP을 받은 경우

1. `CreMore-PasteGuard-windows.zip`을 우클릭하고 **압축 풀기** 또는 **모두 추출**을 선택하세요.
2. 압축을 푼 폴더에서 **CreMore PasteGuard.exe**를 실행하세요.

**실행 결과:** `차단 규칙`, `브라우저 연결`, `차단 기록` 탭이 있는 창이 열립니다.

실행 파일만 따로 옮기지 말고 압축을 푼 폴더 전체를 유지하세요. `CreMore PasteGuard.exe.config` 파일과 `extension` 폴더도 함께 있어야 합니다.

### GitHub에서 소스 코드를 받은 경우

**현재 GitHub Releases에는 실행용 ZIP이 등록되어 있지 않습니다.** GitHub의 **Code → Download ZIP**은 소스 코드를 내려받는 기능이며, 실행 파일은 포함하지 않습니다. 소스 코드만 받은 경우 아래 절차에 따라 실행 파일을 빌드하세요. 이미 앱을 실행했다면 건너뛰어도 됩니다.

<details>
<summary>소스 코드에서 실행 파일 빌드하기</summary>

1. [저장소 첫 화면](https://github.com/kigma00/CreMore-PasteGuard)에서 **Code → Download ZIP**을 선택하세요.
2. 받은 ZIP의 압축을 모두 풀고, **build.ps1** 파일이 있는 폴더를 여세요.
3. 파일 탐색기 주소창에 `powershell`을 입력하고 Enter를 누르세요.
4. 열린 PowerShell 창에서 다음 명령을 실행하세요.

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1
```

5. `Built:`와 실행 파일 경로가 출력되면 빌드가 완료된 것입니다.
6. `dist` 폴더 안의 `PasteGuard` 폴더에서 **CreMore PasteGuard.exe**를 실행하세요.

빌드는 소스 코드로 실행 파일을 만드는 과정입니다. 오류가 발생하면 [빌드 참고](docs/technical-reference.md#빌드)를 확인하세요. 회사 PC에서 실행이 차단되면 관리자에게 문의하세요.

</details>

## 메모장에서 동작 확인

정규식에 일치하는 테스트 문자열은 차단되고, 일반 문장은 붙여넣어지는지 확인합니다. 외부 서비스에 데이터를 전송하지 않고 시험할 수 있습니다.

### 1. 메모장 열기

Windows **메모장**을 실행하고 빈 문서를 여세요.

### 2. 차단 규칙 설정

**규칙**은 차단 대상과 검사할 정규식을 묶은 설정입니다. PasteGuard의 **차단 규칙** 탭에서 다음과 같이 입력하세요. 이미 다른 규칙이 선택되어 있다면 **+ 규칙 추가**를 먼저 누르세요.

| 화면 항목 | 입력값 또는 선택 항목 |
|---|---|
| 규칙 이름 | `메모장 테스트` |
| 앱 실행 파일명 | `notepad.exe` |
| 웹사이트 도메인 | 비워 두기 |
| 검사 패턴 아래 선택 상자 | **테스트 문자열** |
| 규칙 사용 | 체크 |

화면의 **검사 패턴**은 차단할 문자열을 찾는 정규식입니다. 정규식은 문자 종류나 반복 횟수 등의 조건으로 문자열을 검사하는 표현식입니다. **테스트 문자열**을 선택하면 미리 정의된 정규식이 적용되므로 직접 작성할 필요가 없습니다.

입력칸의 회색 예시는 실제 입력값이 아닙니다. 규칙 이름과 대상은 직접 입력하세요.

### 3. 앱에서 정규식 테스트

다음 문자열을 선택하고 `Ctrl+C`로 복사하세요.

```text
PGTEST_ABCD1234EFGH5678
```

PasteGuard의 **테스트** 입력칸에 붙여넣고 **테스트** 버튼을 누르세요.

**예상 결과:** `차단 조건에 해당해요`로 시작하는 결과가 표시됩니다. 이 버튼은 정규식만 검사하며 규칙을 저장하거나 보호를 시작하지 않습니다.

### 4. 저장 후 보호 시작

1. 편집 영역 아래의 **규칙 저장**을 누르세요.
2. 화면 위의 **보호 시작**을 누르세요.
3. 상태가 **Windows 보호 중**으로 표시되는지 확인하세요.

### 5. 실제 붙여넣기 확인

1. 위의 `PGTEST_ABCD1234EFGH5678`을 다시 복사하세요.
2. 메모장의 빈 문서를 클릭하고 `Ctrl+V`를 누르세요.

**예상 결과:** 테스트 문자열이 붙여넣어지지 않습니다. PasteGuard의 **차단 기록** 탭에는 `notepad.exe`와 `메모장 테스트` 기록이 표시됩니다.

이어서 다음 일반 문장을 복사하고 같은 방법으로 붙여넣으세요.

```text
안녕하세요
```

**예상 결과:** 일반 문장은 메모장에 붙여넣어집니다. 복사 직후 검사 준비로 일시 차단되었다면 잠시 기다린 뒤 다시 시도하세요. 다른 규칙이 이 문장을 차단하고 있지 않은지도 확인하세요.

이 테스트 규칙은 `PGTEST_` 뒤에 영문 대문자 또는 숫자 16개가 이어지는 문자열을 찾습니다. 모든 비밀번호나 토큰을 자동으로 탐지하는 설정은 아닙니다.

## Slack과 Notion 앱 보호 설정

1. **+ 규칙 추가**를 누르고 규칙 이름을 입력하세요. 예: `Slack 토큰 보호`.
2. **차단 대상**에서 **+ Slack** 또는 **+ Notion**을 누르세요. 해당 앱의 프로세스 실행 파일명과 웹사이트 도메인이 추가됩니다.
3. **검사 패턴** 아래에서 사용할 유형을 선택하세요. 직접 작성하려면 **직접 입력**을 선택하고 정규식을 입력하세요.
4. **규칙 사용**을 체크하고 **규칙 저장**을 누르세요.
5. 상태가 **Windows 보호 중**인지 확인하세요. 꺼져 있다면 **보호 시작**을 누르세요.

| 검사 유형 | 용도 |
|---|---|
| 테스트 문자열 | 위의 테스트 문자열로 차단 동작 확인 |
| GitHub PAT (classic) | `ghp_` 뒤에 영문 또는 숫자 36개가 이어지는 토큰 형식 검사 |
| 직접 입력 | 사용자 지정 정규식 작성. [입력 예시](#정규식-직접-입력) |

Windows 앱은 이 설정으로 지원하는 붙여넣기 단축키를 검사합니다. Chrome이나 Edge에서 사용하는 Slack 또는 Notion 웹사이트에는 아래 확장 연결도 필요합니다.

## 웹사이트 보호 설정

웹사이트에서는 **브라우저 확장 프로그램**이 붙여넣기를 검사하고 차단합니다. 먼저 **+ 규칙 추가**를 누르고 규칙 이름을 입력하세요. **+ Slack** 또는 **+ Notion**과 **테스트 문자열**을 선택한 뒤 **규칙 사용**을 체크하고 저장하세요.

### 1. 확장 프로그램 설치

1. PasteGuard의 **브라우저 연결** 탭에서 **확장 폴더 열기**를 누르고 폴더 위치를 확인하세요.
2. 브라우저 주소창에 Chrome은 `chrome://extensions`, Edge는 `edge://extensions`를 입력하세요.
3. **개발자 모드**를 켜세요.
4. **압축해제된 확장 프로그램 로드**를 누르세요. 브라우저에 따라 **압축 풀린 파일 로드**로 표시될 수 있습니다.
5. 1번에서 확인한 **extension 폴더**를 선택하세요.

**설치 결과:** 확장 목록에 **CreMore PasteGuard**가 표시됩니다. 폴더 선택 시 앱의 상위 폴더나 개별 파일이 아닌 `extension` 폴더를 지정해야 합니다.

### 2. 연결 키 등록

1. PasteGuard에서 **연결 키 복사**를 누르세요.
2. 브라우저 오른쪽 위의 확장 프로그램 메뉴에서 **CreMore PasteGuard**를 여세요.
3. **Windows 앱 연결 키** 입력칸에 붙여넣고 **연결**을 누르세요.

연결 키는 이 PC의 PasteGuard와 확장을 연결하는 값입니다. GitHub 토큰이나 다른 서비스의 비밀번호를 입력하지 마세요.

### 3. 정책 동기화 및 차단 확인

1. PasteGuard에 규칙이 저장되어 있고 상태가 **Windows 보호 중**인지 확인하세요.
2. **브라우저 확장 창**에서 **정책 새로고침**을 누르세요. 정책은 저장된 규칙과 보호 상태를 뜻하며, 동기화는 이를 확장에 반영하는 과정입니다.
3. **웹사이트 보호 사용 중**이 표시되고 **웹사이트 규칙**에 대상 도메인이 있는지 확인하세요.
4. 보호할 Slack 또는 Notion 웹페이지를 새로고침하세요.
5. `PGTEST_ABCD1234EFGH5678`을 복사하여 입력란에 붙여넣으세요. 메시지를 전송하거나 페이지를 공유할 필요는 없습니다.

**예상 결과:** 테스트 문자열이 붙여넣어지지 않고 페이지에 차단 안내가 표시됩니다.

앱의 **상태 새로고침**은 연결 상태 표시를 갱신합니다. 정책을 즉시 동기화하려면 **확장 창의 정책 새로고침**을 사용하세요. 자동 동기화는 보통 30초마다, 확장 창이 열려 있으면 약 3초마다 이루어집니다. 브라우저 절전 중에는 지연될 수 있습니다.

## 정규식 여러 개 등록

한 규칙에 여러 정규식을 등록할 수 있습니다. **하나라도 일치하면 차단하는 OR 조건**으로 검사합니다.

1. 수정할 규칙을 선택하고 **+ 패턴 추가**를 누르세요.
2. 아래 선택 상자에서 유형을 선택하거나 **직접 입력**으로 정규식을 작성하세요.
3. **규칙 저장**을 누르세요. 웹에도 적용하려면 확장의 **정책 새로고침**을 누르세요.

예를 들어 **테스트 문자열**과 **GitHub PAT (classic)**을 함께 등록하면 두 정규식 중 어느 하나에 일치하는 문자열이 포함되어도 차단합니다.

기존 항목을 선택한 채 유형을 변경하면 해당 정규식이 바뀝니다. 새 정규식은 **+ 패턴 추가**로 등록하고, 삭제할 때는 목록에서 선택한 뒤 **선택 패턴 삭제**를 누르세요.

규칙당 최대 16개, 전체 규칙을 합쳐 최대 100개의 정규식을 등록할 수 있습니다. 빈 항목은 채우거나 삭제해야 저장할 수 있으며, 규칙에는 유효한 정규식이 최소 하나 필요합니다. **테스트** 버튼은 현재 편집 중인 규칙의 모든 정규식을 검사합니다. 실제 보호에는 **규칙 저장** 후 반영됩니다.

## 정규식 직접 입력

다음 예시는 `ghg_` 뒤에 영문 또는 숫자가 한 개 이상 이어지는 문자열을 검사합니다.

1. **검사 패턴**에서 **직접 입력**을 선택하세요.
2. 바로 아래 입력칸에 다음 정규식을 입력하세요.

```text
ghg_[A-Za-z0-9]+
```

3. **테스트** 입력칸에 `ghg_DEMO123`을 입력하고 **테스트**를 누르세요.
4. 차단 조건에 해당하는지 확인한 뒤 **규칙 저장**을 누르세요.

`[A-Za-z0-9]`는 영문 대문자, 소문자 또는 숫자이며, `+`는 앞의 조건이 한 번 이상 반복됨을 뜻합니다. PasteGuard는 정규식의 일부 문법만 지원합니다. [지원 문법과 제한](docs/technical-reference.md#직접-입력-패턴)을 확인하세요.

## 보호 중지와 앱 종료

**보호 중지**는 Windows 앱과 웹사이트 모두에 적용됩니다. Windows 보호는 즉시 중지되고, 웹 보호는 중지 상태가 확장에 동기화된 뒤 중지됩니다.

| 작업 | 방법 |
|---|---|
| 전체 보호 중지 | PasteGuard에서 **보호 중지**를 누르세요. |
| 웹 보호 중지 즉시 반영 | 중지 후 확장에서 **정책 새로고침**을 누르고 **전체 보호 일시 중지** 표시를 확인하세요. |
| 브라우저 연결 해제 | 확장에서 **연결 해제**를 누르세요. 저장된 정책도 삭제됩니다. 다시 사용하려면 연결 키를 등록하세요. |
| 규칙 하나만 비활성화 | 해당 규칙의 **규칙 사용** 체크를 해제하고 **규칙 저장**을 누르세요. 웹에는 정책 동기화 후 반영됩니다. |

**앱 종료와 보호 중지는 다릅니다.** 앱을 종료하면 Windows 보호는 끝나지만, 확장은 마지막으로 받은 정책을 계속 적용할 수 있습니다. 웹까지 중지하려면 종료 전에 중지 상태를 동기화하거나 확장에서 **연결 해제**를 누르세요.

앱을 다시 실행하면 Windows 보호는 꺼진 상태로 시작합니다. 확장도 이 상태를 동기화하면 보호를 중지합니다. 다시 사용하려면 **보호 시작**을 누르고 웹 보호 상태도 확인하세요.

## 문제 해결

| 증상 | 확인할 사항 |
|---|---|
| 입력칸에 예시가 있지만 저장되지 않음 | 회색 예시는 실제 입력값이 아닙니다. 규칙 이름과 대상을 직접 입력하세요. |
| 앱의 테스트는 통과하지만 실제 붙여넣기가 차단되지 않음 | **규칙 저장 → 보호 시작**을 완료했는지 확인하세요. Windows 앱에서는 `Ctrl+V`로 시험하세요. |
| 메모장에서 차단되지 않음 | 앱 실행 파일명이 `notepad.exe`인지, **규칙 사용**이 체크되어 있는지, 테스트 문자열을 정확히 복사했는지 확인하세요. |
| 웹사이트에서 차단되지 않음 | 확장 연결, 보호 상태, 규칙의 도메인을 확인하고 **정책 새로고침** 후 웹페이지를 새로고침하세요. |
| 현재 탭의 검사 모듈이 준비되었다고 표시됨 | 해당 페이지에서 확장이 실행 중이라는 뜻입니다. 페이지의 도메인이 활성 규칙에 포함되어야 보호됩니다. |
| 앱을 종료했는데 웹에서 계속 차단됨 | 확장에서 **연결 해제**를 누르거나, 앱을 다시 실행하여 중지 상태를 동기화하세요. |
| 정규식을 추가한 뒤 저장되지 않음 | 목록의 빈 항목에 정규식을 입력하거나 해당 항목을 삭제하세요. |
| 차단 사유가 검사 한도 초과로 표시됨 | 텍스트 길이나 검사 작업량이 한도를 넘으면 차단할 수 있습니다. 실제 토큰이 발견되었다는 뜻은 아닙니다. |
| 재실행 후 차단 기록이 없음 | 차단 기록은 앱 종료 시 삭제됩니다. 저장한 규칙은 유지됩니다. |
| 화면의 글자가 잘리거나 배율이 맞지 않음 | 실행 파일 옆에 **CreMore PasteGuard.exe.config** 파일이 있는지 확인하세요. |

### 프로세스 실행 파일명과 도메인 직접 입력

- **앱 실행 파일명:** `Slack.exe`처럼 프로세스 실행 파일명을 입력하세요. `C:\...` 같은 폴더 경로는 포함하지 않습니다.
- **웹사이트 도메인:** `notion.so`처럼 입력하세요. `https://`, 페이지 경로, 포트는 포함하지 않습니다.
- 여러 대상은 `Slack.exe, Notion.exe`처럼 쉼표로 구분하세요.
- `*.example.com`은 `app.example.com` 같은 하위 도메인만 포함합니다. 기본 도메인까지 보호하려면 `example.com, *.example.com`을 함께 등록하세요.
- `chrome.exe`나 `msedge.exe`를 앱 대상으로 등록하면 해당 브라우저의 모든 탭이 Windows 규칙의 대상이 됩니다. 특정 사이트만 보호하려면 도메인과 확장 프로그램을 사용하세요.

### 실행 폴더를 옮겨도 되나요?

가능합니다. `dist`는 기본 빌드 출력 위치이며 필수 실행 경로가 아닙니다. 앱을 종료하고 실행 폴더 전체를 쓰기 권한이 있는 위치로 옮기세요.

`CreMore PasteGuard.exe`, `CreMore PasteGuard.exe.config`, `extension`, `README.md`, `README.en.md`, `docs`를 함께 유지하세요. 기존 규칙과 연결 키를 유지하려면 **data 폴더도 함께** 옮겨야 합니다.

이미 확장을 설치했다면 새 위치의 `extension` 폴더를 브라우저에 다시 등록하세요. 확장에 **Windows 앱 연결 필요**가 표시되면 앱에서 **연결 키 복사**를 누르고 확장에 붙여넣은 뒤 **연결**을 누르세요. 연결 키는 Windows 사용자 계정으로 암호화되어 있으므로 다른 PC나 Windows 계정으로 옮겼을 때도 재연결이 필요할 수 있습니다.

### 새 버전으로 업데이트

1. 앱을 종료하고 기존 **data 폴더**를 복사하여 보관하세요. 규칙과 연결 키가 저장된 폴더입니다.
2. 앱 파일과 `extension` 폴더를 새 버전으로 교체하세요. 기존 `data` 폴더는 유지하세요.
3. 브라우저의 확장 관리 화면에서 PasteGuard 확장을 새로고침하세요. 폴더 위치가 바뀌었다면 새 폴더를 등록하세요.
4. 앱을 실행하고 **보호 시작**을 누르세요.
5. 확장에 **Windows 앱 연결 필요**가 표시되면 연결 키로 다시 연결하세요. **정책 새로고침**을 누른 뒤 대상 웹페이지도 새로고침하세요.
6. 테스트 문자열로 차단 동작을 다시 확인하세요.

여러 정규식을 지원하는 1.3.0부터는 **앱과 확장을 함께 업데이트**해야 합니다. 이전 확장은 새 정책 형식을 읽지 못할 수 있습니다. `data` 폴더나 연결 키는 다른 사람에게 보내거나 GitHub에 올리지 마세요.

## 보호 범위와 한계

Windows 앱에서는 실행 중인 PasteGuard가 지정한 프로세스의 붙여넣기 단축키 전달을 차단합니다. 웹에서는 확장이 해당 페이지의 도메인과 텍스트를 검사하고 붙여넣기 이벤트를 취소합니다. 모든 비밀번호를 자동 탐지하거나 모든 입력 경로를 차단하는 기능은 아닙니다.

| 지원하는 동작 | 지원하지 않는 동작 |
|---|---|
| 지정한 Windows 앱의 `Ctrl+V`, `Shift+Insert` 검사 | Windows 앱의 우클릭 메뉴 붙여넣기 차단 |
| 확장이 준비된 웹페이지의 일반 붙여넣기 검사 | 직접 입력, 드래그, 파일 업로드, 다른 앱의 클립보드 직접 읽기 차단 |
| 정규식에 일치하는 문자열 검사 | 토큰의 실제 유효성 확인 또는 Vault와 비교 |
| 현재 실행 중 최근 차단 기록 최대 200건 표시 | 모든 정보 유출 경로 차단 또는 영구 기록 보관 |

지정된 대상에서 검사 준비가 실패하거나 검사 한도를 넘으면 보수적으로 차단할 수 있습니다. 관리자 권한으로 실행한 앱이나 브라우저 내부 페이지 등에서는 보호를 보장하지 않습니다. 확장이 정책을 준비하기 전에는 웹 검사가 적용되지 않을 수 있습니다. [자세한 동작과 예외](docs/how-it-works.md)를 참고하세요.

검사는 이 PC에서 수행합니다. 복사한 원문을 지우거나 외부 서버로 전송하지 않으며 차단 기록에도 원문을 남기지 않습니다. [저장되는 정보](docs/technical-reference.md#차단-기록과-저장-데이터)를 확인하세요.
